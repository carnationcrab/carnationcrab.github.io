Working style

How I approach software

I care about software that stays understandable under pressure: clear interfaces, deliberate ownership, maintainable systems, and projects that are concrete enough to inspect rather than merely describe.

01

Goodish Code first

I bias toward structure first: define the problem, establish the boundaries, and make the implementation legible before layering on convenience.

02

Open source

I like public projects that can be opened, played, or read directly. A runnable build or a visible codebase says more than a polished summary.

03

Learning is doing

I move comfortably between backend work, games, tooling, and teaching projects, but the goal is the same in each case: solve the problem cleanly and leave the system clearer than I found it.

Featured project

Spindle

A long-horizon C++ engine project built around runtime structure rather than visual demo polish. Spindle focuses on the foundations that make larger systems hold together: math primitives, subsystem lifecycle, custom allocators and containers, virtual file system and resource flow, and a disciplined frame loop. It is where I explore engine architecture, low-level tradeoffs, and the kind of systems work that rewards careful design over quick spectacle.
